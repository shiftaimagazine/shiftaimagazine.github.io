# SHIFT AI 기사 다듬기 — 사람이 쓴 글처럼 (2026-10-29~)

매일 아침 기사를 쓴 뒤, 올리기 전에 이 단계를 한 번 거칩니다. 목적은 "AI가 썼다"는 인상을 만드는 문장 습관과 글 짜임을 걷어내는 것입니다. 사실을 바꾸거나 없는 이야기를 넣는 일이 아닙니다.

도구는 사용자가 PC 에 설치한 두 플러그인과 같은 버전입니다(`vendor/README.md`).
- **humanize-korean**(im-not-ai 2.3.2): 10대 분류 85개 패턴, 진단 → 겨냥 윤문 → 의미 보존 게이트. 규칙 ID(C-8, D-8 …)는 이 분류표를 따릅니다. 원본 규칙집: `vendor/im-not-ai/skills/humanize-korean/references/quick-rules.md`, 처방: `rewriting-playbook.md`
- **humanizer-kr**(0.1.10): 과장 칭찬·막연한 권위·챗봇 잔재 같은 짧은 글 규칙(`vendor/humanizer-kr/`)
- 우리 기사용 점검기: `shift_humanize.py` (위 둘의 규칙을 습니다체 뉴스에 맞게 옮김 + BRIEF.md 금지 목록 + 글 짜임 신호)

## 1. 순서 (저장소 루트에서)

```
python3 _src/humanize/shift_humanize.py export --date D     # 기사마다 _workspace/humanize/D/<id>.after.txt 생성
#  → 아래 2~5장 규칙으로 <id>.after.txt 의 문장을 고칩니다(새 에이전트에게 맡기는 것을 권장, 6장)
python3 _src/humanize/shift_humanize.py apply --date D      # 사실 보존 검사 통과분만 _src/news/daily/D.json 에 반영
python3 _src/humanize/shift_humanize.py scan --date D       # 남은 것 확인(S1 0건이어야 assemble.py 통과)
```

- after.txt 는 한 줄이 기사 JSON 의 한 칸입니다. `[[body.3.p]]` 같은 표시는 그대로 두고 뒤의 문장만 고칩니다. 줄을 지우거나 합치거나 새로 만들지 않습니다.
- `##` 줄은 점검기가 그 칸에서 찾은 규칙입니다. 걸리지 않은 칸도 3·4장 기준으로 손볼 수 있습니다.
- apply 가 막는 것: 숫자·영문·따옴표 안 문장이 사라지거나 새로 생김, 칸 수가 달라짐, 한다체 문장 끝, 변경률 50% 이상, verify_gates(humanize-korean 의 의미 게이트) golden 실패. 경고만 하는 것: 변경률 30% 이상, 당위·추측이 단정으로 바뀐 문장(되돌리기 권장).
- apply 를 다시 돌리면 after.txt 기준으로 다시 반영합니다(이미 반영된 기사도 같은 결과). export 를 다시 돌리면 before 만 새로 쓰고 after 는 그대로 둡니다.

## 2. 지킬 것 (가장 중요)

1. **뜻을 바꾸지 않습니다.** 숫자·날짜·가격·고유명사·영문 약어·따옴표 안 인용은 한 글자도 바꾸지 않습니다. 주장의 강도도 그대로입니다. "~할 수 있습니다"를 "~합니다"로, "~로 보입니다"를 단정으로 바꾸지 않습니다.
2. **빼기 위주로 고칩니다.** 원문(공식 발표)에 없는 사실·사례·비유·감상을 넣지 않습니다. 사람 냄새를 내려고 지어낸 경험, 일부러 틀린 맞춤법, 감탄사, 이모지, "~거든요" 같은 구어를 넣지 않습니다.
3. **습니다체를 지킵니다.** 해요체·한다체로 바꾸지 않습니다. 질문은 ~나요?/~ㄹ까요?
4. **고치면서 새 티를 만들지 않습니다.** 지난 기사 진단에서 고친 문장이 "~인 셈입니다"를 새로 넣거나 "볼 수 있습니다"를 단정으로 바꾼 일이 있었습니다. 3장 S1 표현은 고친 문장에도 쓰지 않습니다. 새 쉼표(연결어미 뒤)도 만들지 않습니다.
5. **많이 고치지 않습니다.** 기사 하나에서 바뀐 글자는 10~30%가 알맞습니다. 걸리지 않은 좋은 문장은 그대로 둡니다.

## 5. 글 짜임 다듬기 (점검기가 다 세지 못하는 것 — 기사마다 한 번 봅니다)

StoryScope 연구(arXiv 2604.03136)는 문체를 다듬어도 **글 짜는 방식**에서 AI 글이 93% 가려진다고 했습니다. 우리 기사에서 그게 드러나는 곳은 이렇습니다.

1. **모든 기사가 같은 뼈대.** 리드 → 세 줄 요약 → "무슨 일인가 / 세부 내용 / 왜 중요한가 / 남은 쟁점"이 38편 중 36편에서 반복됐습니다. 소제목을 내용으로 바꾸고, 그날 소식에 맞게 단락 순서도 바꿔도 됩니다(예: 한국 사용자에게 가장 큰 사실을 둘째 단락으로).
2. **의의를 대놓고 설명.** "이번 일은 ~를 보여 줍니다", "~라는 점에서 의미가 있습니다"처럼 해석을 선언하지 말고, 그 해석을 받치는 사실 하나를 씁니다. 해석이 꼭 필요하면 누구의 해석인지 밝힙니다.
3. **보도자료 순서 그대로 옮기기.** 문장마다 "○○은 ~라고 밝혔습니다"로 시작하면 번역한 보도자료처럼 읽힙니다. 문단마다 전달 동사는 한 번이면 충분합니다.
4. **깔끔하게 닫는 결말.** 마지막 문장을 교훈·권고·전망으로 묶지 않습니다. 아직 모르는 것, 다음에 나올 날짜처럼 열린 사실로 끝내도 됩니다.
5. **두루뭉술한 일반론.** "업무 효율이 높아집니다" 대신 원문에 있는 구체적인 예(어떤 화면, 어떤 작업, 몇 초)를 씁니다. 원문에 없는 예는 만들지 않습니다.
6. **같은 사실 되풀이.** 지난 기사 진단에서 "마지막 편집은 기존 도구"가 다섯 번, "광고는 무료·고 요금제에만"이 다섯 번, "86%"가 네 번 나온 기사가 있었습니다. 같은 사실은 리드와 본문 한 곳이면 충분합니다(세 줄 요약·facts 칸은 원래 반복하는 자리라 그대로 둡니다). 점검기는 같은 숫자가 4번 이상이면 REPEAT 로 표시합니다.
7. **단락 끝에 붙인 남는 사실.** 소제목과 상관없는 사실(학생 요금, 다른 앱 요구 사양)을 단락 끝에 덧붙이지 말고, 맞는 단락으로 옮기거나 빼도 되는지 봅니다(뺄 때는 숫자 검사에 걸리니 다른 칸으로 옮깁니다).
8. **고른 리듬.** 문단마다 긴 문장 하나(80~130자)와 짧은 문장 하나가 섞이게 합니다. 같은 끝맺음이 줄줄이 이어지지 않게 합니다.

## 6. 누가 다듬나

humanize-korean 의 실측에 따르면 글을 쓴 같은 대화가 스스로 고치면 매끄러운 구조 티를 잘 못 봅니다. 그래서 **Agent 도구로 새 에이전트(general-purpose)를 하나 띄워** 다듬게 하는 것을 기본으로 합니다. 에이전트에게 줄 지시(그대로 복사):

> 저장소 `_src/humanize/HUMANIZE.md` 를 처음부터 끝까지 읽고, `_workspace/humanize/<D>/` 의 `*.after.txt` 파일들을 그 규칙대로 고쳐 주세요. 3장(S1)은 모두 고치고, 4장(S2)과 5장은 `##` 표시가 있는 칸 위주로 고칩니다. 원문과 비교할 때는 같은 폴더의 `*.before.txt` 를 보고, 사실 확인이 필요하면 `_src/news/daily/<D>.json` 의 verify·sources 를 봅니다. 파일은 after.txt 만 고치고 다른 파일은 건드리지 않습니다. 끝나면 기사마다 고친 곳 수와 바꾼 소제목을 한 줄로 알려 주세요.

에이전트가 끝나면 기사를 쓴 쪽이 apply 를 돌리고, 막힌 칸이나 남은 S1 을 직접 고쳐 다시 apply 합니다. Agent 도구가 없으면 직접 고칩니다.

## 7. 고친 예 (우리 기사에서)

- 소제목(TPL) — 2026-10-28 애플 기사: "무슨 일인가 / 왜 중요한가 / 남은 쟁점" → "세 앱에서 비서가 맡는 일 / 챗봇 창을 오가던 단계가 줄어듭니다 / 한국어 일정과 문서 권한"
- 전달 동사(REPORT) — "애플은 이번 비서가 문서의 맥락을 이해해서 사용자가 작업 화면을 떠나지 않고 일을 처리하도록 돕는다고 설명했습니다." → "이번 비서는 문서의 맥락을 이해해서 사용자가 작업 화면을 떠나지 않고 일을 처리하도록 돕습니다."
- 두 문장 잇기(E-1·REPORT) — "애플은 세 앱의 새 MCP 지원으로 … 실행할 수 있다고 밝혔습니다. 발표문은 어떤 외부 AI 앱이 연결되는지 이름을 들지 않았습니다." → "세 앱에 MCP가 들어오면 외부 AI 에이전트와 도구가 문서 내용을 읽고 편집하고 자동 작업까지 실행할 수 있게 되지만, 어떤 외부 AI 앱이 연결되는지는 발표문에 이름이 나오지 않습니다."
- 쉼표(C-11) — "연 129달러이고, 신규 구독자는" → "연 129달러이고 신규 구독자는"
