# SHIFT AI 매거진 — 기사 작성 브리프 (공통)

SHIFT AI는 한국어 AI 웹 매거진이다(https://shiftaimagazine.github.io). 독자가 "그래서 무엇이 달라지는가"를 끝까지 읽는 곳이다. 매일 작업은 최근 24~48시간 안에 원문이 나온 소식만 다룬다.

## 1. 출처 규칙 (가장 중요)
- **원문(1차 출처)만 출처로 쓴다.** 허용: 회사·기관의 공식 블로그/뉴스룸/보도자료, 공식 문서·가격 페이지·도움말, 회사 또는 당사자의 공식 X(트위터) 글, 당사자가 쓴 레딧 글, 깃허브 저장소/릴리스, 논문(arXiv 등)·연구기관 보고서, 정부·의회·법원 문서, 연구를 직접 수행한 회사의 리서치 블로그(예: wiz.io, redact.dev).
- **금지: 언론사 기사**(TechCrunch, The Verge, WIRED, Reuters, CNBC, VICE, Bloomberg, Ars Technica, VentureBeat, MarkTechPost, Pocket-lint, The Next Web, PPC Land, 전자신문, AI타임스 등), 뉴스 요약 블로그, 유튜브 해설 영상. 언론 기사는 **원문을 찾는 실마리로만** 쓰고 sources에 넣지 않는다.
- 원문을 직접 열어(WebFetch) 확인한 URL만 쓴다. 열지 못했거나 못 찾았으면 그 주제는 **쓰지 말고** `dropped`에 이유를 적는다. 지어내지 않는다.
- 숫자·날짜·가격·인용은 원문에서 확인한 것만. 회사가 스스로 낸 성능·실적 수치에는 "(자체 발표 기준)"을 붙인다. 원문에 없는 해석은 "왜 중요한가" 단락에서 분석으로만 쓴다.
- 언론 기사 문장을 번역·요약해 옮기지 않는다. 원문 사실을 바탕으로 **새로 쓴다**.

## 2. 문체
- 기사체 "~다". 인스타 캡션 말투("~했어요", 이모지, 감탄) 금지. 독자에게 직접 묻는 문장은 `ask` 한 곳에만.
- 회사·제품명은 처음에 한글(영문) 병기: 문샷AI(Moonshot AI). 이후 한글.
- 길이: 본문 1,300~2,200자(공백 제외 대략). 너무 길게 늘이지 않는다.
- 구조(이 순서):
  1) `lead`: 2~3문장. 누가·언제·무엇을·왜 중요한지.
  2) `ul`: 핵심 3줄 ([제목, 설명] 3개).
  3) `h` + `p` 단락 3~4개. 권장 소제목: "무슨 일인가" / "세부 내용" / "왜 중요한가" / "남은 쟁점" 또는 "무엇을 해야 하나". 주제에 맞게 바꿔도 된다.
  4) 비교·수치가 있으면 `table` 하나(선택).
- `try`: **"오늘 바로 해 볼 것"** 한 문장(60~100자, 120자 이내). 기사 맨 위에 보인다. 독자가 오늘 직접 해 볼 수 있는 구체적인 행동 하나(설정 확인, 써 보기, 원문에서 찾아보기, 담당자에게 묻기 등). 기사 속 확인된 사실에만 기대고, 과장·투자 권유·결과 약속은 하지 않는다. 예: "챗GPT 플러스 이상을 쓴다면 자주 하는 작업 하나를 GPT-6.1 테라로 돌려 보고, 지금 쓰는 모델과 속도·결과를 비교해 본다." (2026-10-28 기사부터 필수)
- `facts`: "한눈에 보기" 표. 4~6행. [라벨, 값]. 라벨 예: 발표 주체 / 날짜 / 무엇 / 핵심 숫자 / 대상·지역 / 원문.
- `ask`: 독자에게 남기는 질문 한 문장(~나/~까 체).

## 3. 카테고리 (cat) — 하나 고르기
"모델·제품" | "보안·안전" | "정책·저작권" | "비즈니스·일자리" | "연구" | "커뮤니티·문화"

## 4. 출력 형식 (JSON 파일 하나)
```json
{
  "articles": [ { ...기사... } ],
  "dropped": [ {"topic": "...", "reason": "원문을 찾지 못함 / 언론 보도만 있음 / ..."} ]
}
```
기사 객체:
```json
{
  "id": "2026-10-21-php2shell",                 // 게시 날짜(KST)-영문슬러그
  "cat": "보안·안전",
  "date": "2026-10-21",                          // 매거진에 올린 날짜(KST) = 그날 데일리 이슈 날짜. 원문 발표일은 facts 의 "날짜" 행과 본문에 쓴다
  "time": "18:40",                               // 올린 시각(KST, HH:MM). 그날 기사끼리는 lead 가 가장 늦은 시각
  "title": "AI가 찾아낸 PHP 취약점, 웹의 70%가 영향권",   // 기사 제목(40자 안팎)
  "sub": "PHP2Shell · 패치 공개 당일 일부 사이트 일시 폐쇄", // 부제
  "hook": "목록에 보이는 요약 1~2문장(120~180자)",
  "facts": [["발표 주체","위즈(Wiz) 리서치"],["날짜","2026년 10월 21일"],["무엇","PHP 엔진 원격 코드 실행 취약점"],["영향 범위","PHP 사용 웹사이트(웹의 약 70%)"],["원문","wiz.io 블로그"]],
  "body": [
    {"lead": "..."},
    {"ul": [["PHP 엔진 자체의 결함","로그인 없이 원격 코드 실행 가능"],["AI로 찾고 공격까지 검증","제미나이·GPT 활용"],["10월 21일 패치 공개","..."]]},
    {"h": "무슨 일인가"}, {"p": "..."},
    {"h": "세부 내용"}, {"p": "..."},
    {"table": {"head": ["항목","값","비고"], "rows": [["...","...","..."]], "note": "출처·기준일"}},
    {"h": "왜 중요한가"}, {"p": "..."}
  ],
  "ask": "운영 중인 사이트의 마지막 업데이트는 언제였나.",
  "sources": [["위즈 리서치 — PHP2Shell", "https://wiz.io/blog/php2shell-php-rce"]],
  "terms": ["취약점"],                     // 아래 용어 목록에서 해당하는 것만
  "image": {"page": "대표 이미지를 가져올 원문 페이지 URL", "og": "원문의 og:image URL(모르면 null)", "credit": "이미지: 회사명(영문 가능)", "alt": "이미지 설명", "mode": null},
  "verify": [{"claim":"웹의 약 70%가 PHP 사용","url":"https://wiz.io/...","quote":"원문에서 해당 문장 그대로(영문 가능)"}]
}
```
- `image`: 사진은 GitHub Actions가 og 주소 → 원문 페이지의 og:image → 원문 첫 화면 캡처 순서로 받아 붙인다(img/ph/<id>.webp). 회사 공식 이미지·보도 사진·제품 화면이 우선. AI로 만든 그림으로 보이면 `"mode": "screenshot"`(원문 화면 캡처)으로 바꾼다. 언론사 사진은 쓰지 않는다.
- `verify`는 화면에 안 나온다. 기사 속 **모든 숫자·날짜·인용**마다 하나씩, 원문 문장을 그대로 붙인다(검수용).
- 용어(terms): `_src/news/terms.json` 의 `t` 값만 쓴다(AI 용어와 API·SDK·GPU 같은 IT 용어가 함께 있다). 새 용어는 {t, en, i(첫 초성 또는 알파벳 대문자), g(AI | 제품·회사 | 개발 | 인프라 | 보안·개인정보 | 비즈니스·정책), d(한두 문장 풀이), rel(관련 기사 id 또는 null)} 로 추가한다.

## 5. 작업 방식
- 주제마다 WebSearch로 원문을 찾고 WebFetch로 열어 확인한다. 주제당 검색·열람 4회 안팎, 전체 50회 안쪽.
- 다 쓰면 파일을 `python3 -c "import json;json.load(open(PATH))"`로 검사한다.
- 마지막 보고: 쓴 기사 수, 버린 주제와 이유, 원문이 약한(확인이 일부만 된) 기사 목록. 5줄 안쪽.
