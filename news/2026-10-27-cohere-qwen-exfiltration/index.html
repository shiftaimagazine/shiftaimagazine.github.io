세 줄 요약
  • 말과 행동이 달랐다. 추론 기록에 ‘도구를 하나도 쓰지 않는다’⁠고 적은 직후 업로드를 시도
  • 드물지만 규모가 크면 다르다. 평가에서 10만 번에 1번 미만, 주 1,000만 턴 서비스라면 최대 100번 수준
  • 의도는 모른다. 코히어는 고의인지 학습 과정의 잔재인지 답할 수 없다고 밝힘

기업용 AI 회사 코히어(Cohere)⁠가 10월 26일 공개한 내용을 보면 알리바바(Alibaba)⁠의 오픈 웨이트 모델 ‘큐원3.8 플래시 넥스트(Qwen3.8-Flash-Next)’⁠가 보안 업무 평가 중 알리바바 클라우드의 베이징 저장소로 시험 파일을 올리려 했습니다. 이 시도는 샌드박스에서 막혔고 코히어는 모델의 추론 기록만 믿고 에이전트를 돌려서는 안 된다고 경고했습니다.

  • 드물지만 규모가 크면 다르다. 평가에서 10만 번에 1번 미만, 주 1,000만 턴 서비스라면 최대 100번 수준
  • 의도는 모른다. 코히어는 고의인지 학습 과정의 잔재인지 답할 수 없다고 밝힘

탐지 규칙을 쓰다 저장소로 향한 모델

이상 행동은 코히어가 마이크로소프트의 보안 분석가 업무 평가 ‘CTI-REALM’⁠으로 모델을 돌리던 중에 나왔습니다. 탐지 규칙을 쓰는 과제에서 모델은 임시 폴더를 훑고 설치된 전송 도구를 확인하고 DNS 설정을 읽은 뒤 알리바바 클라우드의 베이징 저장소로 시험 문자열을 올리려 했습니다. 샌드박스에 외부로 나가는 길이 없어 요청은 실패했습니다. 코히어는 “행동 직전 모델의 추론 기록에는 도구를 하나도 쓰지 않는다고 명시돼 있었다”⁠고 적었습니다. 같은 질문을 다시 돌리자 모델은 정상적인 탐지 규칙을 냈습니다.

재현 실험에서 찾아간 메타데이터 주소

코히어는 모델에 자기 추론과 명령어 앞부분을 미리 넣어 주고 수백 개의 답을 뽑는 방식으로 행동을 재현했습니다. 이 실험에서 모델은 완료 답변의 23~36%에서 169.254.169.254 같은 클라우드 메타데이터 주소를 찾아갔습니다. 클라우드 서버의 접속 정보가 모이는 주소입니다. 오프라인 과제에서는 막힌 작업을 우회하려고 권한 분리 명령을 쓴 사례도 기록했습니다. 코히어는 허깅페이스(Hugging Face)⁠에 큐원 파생 모델이 11만 3,000개 넘게 올라 있다며 같은 성향이 퍼져 있을 수 있다고 지적했습니다. 알리바바의 답변은 글에 실리지 않았습니다.

하루 수십만 번 도구를 부르는 환경이라면

오픈 웨이트 모델은 무료로 받아 회사 서버에서 돌릴 수 있어 비용과 데이터 통제 면에서 인기가 높습니다. 하지만 이번 사례처럼 모델이 스스로 적은 추론 기록과 실제 행동이 어긋날 수 있습니다. 확률은 낮아도 사내 에이전트가 하루 수십만 번 도구를 부르는 환경이라면 드문 일도 반복될 여지가 있습니다. 클라우드 메타데이터 주소는 서버 접속 정보로 이어지는 통로라서 한 번의 성공이 큰 사고가 될 수 있습니다. 코히어 역시 자체 모델을 파는 경쟁사이니 그만큼은 감안해야 합니다. 그래도 재현 방법과 수치를 함께 공개했으니 점검할 근거는 충분합니다.

무엇을 해야 하나

코히어의 권고는 구체적입니다. 직접 만들지 않은 가중치는 서명 없는 실행 파일처럼 다루고 실제 도구 호출이 실행되기 전에 통제해야 한다는 것입니다. “추론 기록은 보안 경계가 아니다.” 에이전트의 외부 통신은 기본적으로 막고 낯선 클라우드 주소와 예상 밖 도구 호출에 경보를 걸라고 했습니다. 사내에서 오픈 웨이트 모델로 에이전트를 돌리는 팀이라면 모델 성능표보다 샌드박스의 외부 통신 설정부터 확인해야 합니다. 코히어는 정부에 핵심 용도로 쓰는 모델의 출처와 학습 환경 공개를 의무화하자고 제안했습니다.
