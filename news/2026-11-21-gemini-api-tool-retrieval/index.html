구글⁠(Google)⁠이 11월 19일(미국 시각) 제미나이 API에 도구 검색(Tool Retrieval)⁠을 내놓았습니다. 에이전트가 연결된 도구의 매개변수 정보를 요청마다 전부 보내지 않고 필요할 때만 불러오게 하는 기능이며, 인터랙션스 API(Interactions API)⁠에서 미리보기로 열렸습니다.

  • 제미나이 3.6 이상과 제미나이 4 전 모델. 인터랙션스 API에서 미리보기로 열렸습니다

도구가 수백 개가 되면 생기는 일

에이전트가 도구 수십 개에서 수백 개에 연결되면 요청마다 모든 도구의 매개변수 스키마를 보내는 비용이 빠르게 커집니다. 구글은 이 방식이 입력 토큰 수와 지연 시간을 늘리고 후보 목록이 길어질수록 도구 선택 정확도를 떨어뜨린다고 설명합니다. 도구 검색은 모델이 먼저 도구 이름과 설명만 보고 필요한 도구를 고른 뒤 그 도구의 스키마만 받아 가는 구조입니다. 인덱스를 만들거나 따로 호스팅할 필요는 없습니다.

설정은 두 곳만 고치면 됩니다

요청의 tools 배열에 tool_search 도구를 넣고 나중에 불러올 도구마다 defer_loading을 true로 지정합니다. 원문 코드 예시는 파이썬에서 client.interactions.create를 부르며 모델 이름으로 gemini-⁠4-hydrogen을 썼습니다. 응답의 interaction.steps에는 tool_search_call, tool_search_result, function_call 단계가 차례로 나타납니다.

자체 도구 저장소를 쓰는 경우 tool_search에 execution을 client로 지정하고 검색 결과를 function_result로 돌려줍니다. 원격 MCP 서버는 mcp_server 도구에 defer_loading을 켜면 서버의 모든 도구가 필요할 때 로드됩니다.

토큰이 줄어드는 조건과 청구 방식

도구 검색 자체에는 별도 요금이 없고 입력과 출력 토큰은 호출한 모델의 표준 요금으로 계산됩니다. 다만 tool_search를 켜면 고정된 소량의 입력 토큰이 더해지고 모델이 불러온 스키마는 대화가 끝날 때까지 입력으로 청구됩니다. 원문은 불러오지 않는 스키마가 불러오는 스키마보다 많을 때 토큰이 절약되며 큰 도구 모음에서는 보통 그렇다고 적었습니다. 정확도나 절감률 같은 구체적인 수치는 원문에 없고 실제 트래픽으로 직접 재 보라는 안내만 있습니다.
