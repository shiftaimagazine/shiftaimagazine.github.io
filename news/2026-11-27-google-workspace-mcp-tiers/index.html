구글이 11월 24일(미국 시각) 구글 워크스페이스(Google Workspace) MCP 서버와 명령줄 도구⁠(CLI)⁠를 정식 출시하고 지메일⁠·드라이브⁠·캘린더 API 사용량을 표준과 확장 두 단계로 나눴습니다. AI 에이전트가 워크스페이스 데이터를 쓰려면 REST API를 직접 부르지 않고 MCP를 거쳐야 하며 기술적 강제는 2027년 2월 1일에 시작됩니다.

에이전트의 출입구가 MCP 서버로 모입니다

구글이 직접 운영하는 MCP 서버는 클라우드와 웹에서 도는 AI 에이전트가 지메일, 드라이브, 문서, 시트, 슬라이드, 캘린더, 챗, 태스크의 미리 만들어 둔 도구를 부르는 통로입니다. 킵⁠(Keep)⁠은 준비 중입니다. 터미널에서 일하는 에이전트에게는 CLI가 따로 있고 에이전트용 스킬 묶음과 범위를 좁힌 로그인이 들어 있습니다. 블로그는 MCP 도구가 워크스페이스 경계 안에서 정리한 요약을 돌려주고 CLI는 여러 도구를 한 번에 엮을 수 있어서 토큰 비용과 지연이 줄어든다고 설명했습니다. 두 기능 모두 모든 워크스페이스 고객과 개발자가 쓸 수 있고 관리자 설정과 사용량 대시보드는 2주 안에 순차 적용됩니다.

무료 표준 단계와 4월부터 청구되는 확장 단계

표준 단계는 비용이 없고 정식 MCP 서버 기준으로 프로젝트당 제품별 하루 5,000건까지 요청할 수 있으며 구글 클라우드 청구 계정도 카드도 필요하지 않습니다. 한도를 넘으면 시간 창이 초기화될 때까지 요청이 늦춰집니다. 구글에 따르면 활성 개발자의 99% 넘게가 표준 단계에 있습니다(자체 발표 기준). 확장 단계는 청구 계정을 연결한 프로젝트가 쓰며 과금은 2027년 4월 1일에 시작하고 그 전에는 청구하지 않습니다. 지메일⁠·캘린더⁠·드라이브의 MCP 사용량에는 하루 무료 허용량이 없어서 첫 요청부터 청구 대상이 됩니다. 돈을 내는 쪽은 프로젝트에 연결된 청구 계정의 개발자이고 최종 사용자에게 청구한다는 내용은 두 문서에 없습니다.

외부 AI 앱을 쓰는 조직이 볼 관리자 설정

관리자는 관리 콘솔의 보안 아래 API 제어에서 외부 AI 도구와 MCP 서버, CLI, API 접근을 관리하고 사람이 확인하는 규칙과 에이전트 감사 로그를 설정할 수 있습니다. 외부 AI 에이전트는 OAuth 로그인 때 자신을 밝히고 워크스페이스 MCP 서버를 거쳐 연결해야 합니다. 초안 작성 같은 일상 작업은 그대로 매끄럽게 두고 외부 파일 읽기나 데이터 공유처럼 민감한 작업에만 사용자 확인을 걸 수 있습니다. 2027년 2월 1일부터 적용되는 워크스페이스 AI 도구 부속 약관에는 API에서 받은 데이터를 오래 저장하거나 워크스페이스 API를 긁어 가는 행위의 금지가 들어 있습니다.

요금표와 지메일 발송 기능은 아직 나오지 않았습니다

확장 단계의 요금은 라이트, 미디엄, 플러스, 프리미엄 네 구간으로 나뉘고 작업의 자원 사용량과 복잡도, 데이터 크기에 따라 정해집니다. 드라이브는 네 구간을 모두 쓰고 지메일은 세 구간, 캘린더는 한 구간을 씁니다. 두 문서에는 달러 금액이 없습니다. 지메일 MCP가 메일을 직접 보낼 수 있는지도 언급이 없으며 초안 작성이 매끄럽게 유지된다는 말만 있습니다. 다른 접근 방식에 대한 사용량 단계는 앞으로 몇 달 안에 바뀔 예정입니다.
