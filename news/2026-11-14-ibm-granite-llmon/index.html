IBM 그래니트(Granite) 팀이 11월 12일 허깅페이스(Hugging Face) 블로그에서 LLMON이라는 입력 형식을 소개하고, 이 형식으로 학습한 실험용 모델 granite-⁠4.1-3b-LLMON-preview와 granite-⁠4.1-8b-LLMON-preview를 내놨습니다. LLMON(LLM Object Notation)⁠은 '레몬'으로 읽으며, 지시와 데이터의 경계를 모델 전용 기호로 표시해 외부 문서에 숨은 명령을 따르는 문제를 줄이려는 형식입니다.

  • 실험용 미리보기. 원문이 프로덕션에는 맞지 않는다고 적었습니다

JSON 대신 모델 전용 구분 기호를 씁니다

원문은 JSON이 파서에 맞춰 설계된 형식이라고 말합니다. 토크나이저는 JSON 문법을 강제하지 않아서 중괄호⁠·따옴표⁠·콜론 토큰이 일반 글에도 나옵니다. 중첩 깊이도 괄호 수를 세어 알아내야 하는데 트랜스포머는 긴 구간에서 이 계산에 약하다는 설명입니다. LLMON은 XML과 비슷한 마크업이면서 구분 기호를 문자가 아닌 예약된 특수 토큰으로 둡니다. 태그에는 고유 ID가 붙어 문맥 어디에 있는 지시든 가리켜 데이터에 묶을 수 있고, 블록 하나를 가리키는 데는 어떤 ID를 쓰든 토큰이 두 개 듭니다. 기존 채팅 템플릿에 덧붙여 쓰는 형식이며, 이미 있는 JSON은 변환기로 손실 없이 LLMON으로 바꿨다가 되돌릴 수 있습니다.

외부 문서 속 명령에 얼마나 넘어가는지 쟀습니다

시험은 OPI, ASB, StruQ 세 가지 벤치마크이고 방어력은 1에서 공격 성공률을 뺀 값입니다. 팀은 OPI에서 이 문제가 사실상 사라졌다고 평가했습니다. 시험한 최고 프런티어 모델보다 공격을 47% 더 피했고 최고 오픈소스 모델보다는 95% 더 피했다는 내용입니다. ASB와 StruQ에서도 비슷한 경향이 나왔지만 점수는 글에 적혀 있지 않고 차트 그림으로만 실렸습니다. 일반 능력은 그래니트 4.1 인스트럭트 모델과 같은 수준이라고 합니다.

학습 방식과 남은 한계

모델은 그래니트 4.1 기본⁠(base) 체크포인트에서 출발했고 공개된 인스트럭트 모델은 쓰지 않았습니다. 추론⁠·RLHF⁠·지식 보정⁠·수학을 다루는 GRPO 강화학습 단계를 다섯 번 거친 뒤 온폴리시 선호 쌍 천 개로 DPO를 한 번 더 했습니다. 팀은 이 방어가 학습으로 얻은 행동이며 강제되는 보장은 아니라고 적었습니다. 시험도 고정된 간접 프롬프트 주입만 다루고, 상대에 맞춰 바뀌는 여러 턴 공격은 대응을 연구하는 중입니다. 라이선스는 글에 나와 있지 않습니다.
