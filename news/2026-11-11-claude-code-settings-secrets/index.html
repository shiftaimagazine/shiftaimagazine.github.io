클로드 코드 설정 파일 1,122개에 비밀 노출

클라우드 보안 연합(Cloud Security Alliance, CSA)⁠이 11월 8일 낸 연구 노트가 클로드 코드(Claude Code) 설정 파일에 비밀번호와 키가 평문으로 남아 공개 GitHub 저장소에 올라간 사례를 정리했습니다. 아피로⁠(Apiiro)⁠가 공개 저장소에서 .claude/settings.local.json 사본 104,185개를 찾아 보니 1,122개에 비밀이 하나 이상 들어 있었다고 합니다.

오늘 바로 해 보세요클로드 코드를 쓴다면 프로젝트의 .claude/settings.local.json을 열어 비밀번호나 토큰이 들어간 allow 줄이 없는지 확인해 보세요.

승인 한 번이 평문 기록이 됩니다

클로드 코드의 권한 창에서 ‘Yes, and don't ask again’⁠을 누르면 승인한 명령이 프로젝트의 .claude/settings.local.json 파일에 allow 규칙으로 저장됩니다. CSA 노트는 이 규칙이 승인된 명령 문장을 그대로 기록한다고 설명합니다. 그래서 PGPASSWORD=나 sshpass -p, mysql -p처럼 명령줄 안에 쓴 비밀번호가 파일에 그대로 남습니다. 클로드 코드는 처음 쓸 때 이 파일을 사용자 전역 git 제외 목록에 넣지만 프로젝트의 .gitignore에는 넣지 않으며, 사용자가 직접 만든 파일은 .gitignore에 직접 넣어야 합니다.

공개 사본 104,185개를 뒤진 결과

아피로는 공개 GitHub의 저장소 103,617곳에서 이 파일의 사본 104,185개를 찾았고 그중 1,122개(약 1.1%)⁠에 비밀이 하나 이상 있었습니다. 현재 사본에서 나온 비밀에는 데이터베이스 비밀번호 379개, 공개 서버 SSH 로그인 43개, AWS 키 23개가 들어 있습니다. git 이력에만 남은 비밀도 734개이고, 공유 설정 파일 .claude/settings.json과 에이전트 채팅 로그까지 합치면 1,994개 저장소에서 2,539개입니다. 이 파일이 기본 브랜치에 있던 저장소의 절반에서는 최소 217일 동안 그대로 올라가 있었습니다.

숫자를 읽을 때 알아 둘 점

아피로의 글 자체는 이번에 열리지 않아서 위 숫자는 CSA 노트에 옮겨 적힌 것을 따랐습니다. 노트에 따르면 아피로는 남은 비밀이 지금도 작동하는지 시험하지 않았고, CSA도 이 조사를 독립적으로 재현하지 않았습니다. 노트가 인용한 GitHub 이슈 #5544는 2025년 8월 11일에 올라와 2026년 1월 3일 자동 봇이 계획 없음으로 닫았으며 유지보수자의 응답은 없었습니다. 앤트로픽의 공식 입장은 노트에 실려 있지 않습니다.

이미 올렸다면 키부터 바꿉니다

노트가 정리한 권고는 순서가 있습니다. 먼저 노출된 자격 증명을 새것으로 바꾸고, 그다음 git rm -⁠-⁠cached .claude/settings.local.json 으로 추적을 끊은 뒤 저장소 .gitignore에 넣고 git check-ignore -v로 확인합니다. 파일을 지우거나 이력을 다시 쓰는 것만으로는 이미 퍼진 사본이 없어지지 않습니다. 명령에 비밀을 직접 쓰는 대신 $DB_URL 같은 환경 변수를 쓰고 특정 명령 대신 Bash(npm run *) 같은 패턴 규칙을 쓰라고도 권하는데, curl이나 ssh, 데이터베이스 클라이언트처럼 넓은 패턴은 실행 위험을 키울 수 있다고 노트는 덧붙입니다.
