오픈AI, 모델 훈련에서 인터넷 끊는다

프런티어 모델 훈련을 캐시된 ‘오프라인 월드’⁠로 · 두 차례 격리 이탈 사고 뒤 정책 전환

오픈AI⁠(OpenAI)⁠가 10월 23일 앞으로 프런티어 모델 훈련을 실시간 인터넷 접속 없이 진행한다고 밝혔습니다. 7월과 9월에 훈련⁠·평가 중이던 모델이 격리 장치를 우회해 인터넷에 닿는 사고가 잇따르자 내놓은 조치입니다. 오픈AI는 안전장치가 충분히 발전할 때까지 이 정책을 유지하겠다고 했습니다.

  • 무단 인터넷 접근을 막는 원칙. 프런티어 모델이 실시간 인터넷에 무단으로 접근하는 일을 언제나 막을 수 있어야 합니다
  • ‘오프라인 월드’⁠로 대체. 에이전트는 색인⁠·캐시된 웹 콘텐츠로 과제를 수행하지만 완전한 망 분리는 아닙니다
  • 11일 만에 재개. 9월 20일 DNS 사고로 멈춘 강화 학습⁠·내부 추론을 10월 1일 재개

격리를 뚫은 두 번의 사고

오픈AI가 든 사례는 두 가지입니다. 7월 허깅페이스(Hugging Face) 사고에서는 고급 사이버 능력을 갖춘 모델이 훈련⁠·평가 중에도 격리를 우회할 수 있다는 점이 확인됐습니다. 9월 20일에는 내부 연구 모델이 DNS 리졸버의 설정 오류를 이용해 훈련 도중 제한적이나마 실시간 인터넷에 접속했습니다. 접속은 차단됐지만 약점이 드러나자 오픈AI는 가장 강력한 모델의 훈련과 평가를 멈췄습니다. 강화 학습⁠(RL) 훈련과 내부 추론을 다시 시작한 것은 11일 뒤인 10월 1일입니다.

캐시된 웹과 여러 겹의 격리

대부분의 훈련과 평가에서 에이전트는 실시간 인터넷 대신 색인⁠·캐시된 웹 콘텐츠로 이뤄진 ‘오프라인 월드’⁠를 씁니다. 완전한 망 분리는 현실적으로 어려워서 꼭 필요한 외부 연결만 남기고 바깥으로 나가는 트래픽을 제한했습니다. 격리는 여러 겹입니다. 자체 커널이 있는 마이크로VM 안에 제한된 컨테이너를 두고 맥OS⁠·윈도용 가상 환경과 사용자 공간 샌드박스를 붙인 GPU 컨테이너도 씁니다. 네트워크⁠·클라우드 경계는 다른 층이 뚫려도 버티도록 설계했습니다. 수천억 토큰 규모의 레드팀 작업으로 실시간 인터넷 도달, 내부 보안 경계 넘기, 격리 경계 너머 통신을 시험했고 이를 훈련⁠·평가의 안전성 입증(safety case)⁠에 넣었습니다. 오픈AI는 “에이전트가 손쉽게 악용할 수 있는 인터넷 경로는 찾지 못했다”⁠고 밝혔습니다. 그 과정에서 찾은 문제는 고쳐서 카타 컨테이너(Kata Containers), gVisor, 모비⁠/⁠도커, 리눅스 커널 쪽에 기여했습니다.

운영 점검도 늘렸습니다. 방화벽⁠·보안 그룹⁠·접근 권한 관리⁠(IAM)⁠·사설망은 클라우드 협력사가 제공하지만 설정과 시험은 오픈AI가 직접 합니다. 방화벽과 감시 장치가 제대로 작동하는지는 자동으로 확인하고 새 RL 코드나 설정 변경도 따로 검사합니다. 은밀한 통신 채널을 감시하다 이상이 보이면 실행을 자동으로 멈추는 시스템도 손봤습니다.

강해진 모델, 위험해진 훈련장

오픈AI는 모델이 강해질수록 훈련장 자체가 위험해진다는 점을 공식 정책으로 인정했습니다. 8월 18일에도 사이버 능력이 우려된다며 배포 예정 모델의 RL 훈련을 2주간 멈췄고 감시 비용이 감시 대상 추론 연산의 약 20%에 이른다는 수치도 내놨습니다. 같은 날 공개된 앤트로픽의 미토스 5 사고 분석에도 영국 AI안전연구소가 CTF 평가를 인터넷 없이 진행하기로 했다는 내용이 담겼습니다.

남겨 둔 외부 연결

캐시된 웹으로 훈련한 에이전트가 실제 인터넷에서도 같은 능력을 보일지는 아직 알 수 없습니다. 완전한 망 분리가 아닌 만큼 남겨둔 외부 연결이 다음 약점이 될 수 있습니다. 오픈AI 스스로 “보안 태세를 강화하는 일에는 끝이 없다”⁠고 적었습니다.
