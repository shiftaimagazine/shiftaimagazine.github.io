왜 필요한가요클로드 코드는 요청할 때마다 지금까지의 대화 전체를 다시 보냅니다. 캐시 덕분에 다시 읽는 부분은 낮은 요율로 계산되지만, 하루 종일 열어 둔 세션에서는 한 줄짜리 질문도 쌓인 대화 전체만큼 사용량을 씁니다.
클로드 코드(Claude Code)는 요청마다 대화 기록, CLAUDE.md 같은 지시 파일, Claude가 읽은 파일 내용을 함께 모델에 보내고, 토큰 비용은 이 컨텍스트의 크기에 따라 늘어납니다. 프롬프트 캐싱과 자동 압축은 이미 알아서 돌아가므로, 사용자는 컨텍스트를 작게 유지하고 일에 맞는 모델과 추론 수준을 고르면 됩니다. 아래 7단계는 클로드 코드에 들어 있는 명령과 설정만 다루며, 2026년 10월 27일 기준 공식 문서에서 확인했습니다.

STEP 1어디에 쓰고 있는지 먼저 보기3분

이 단계에서는 /usage와 /context로 사용량이 어디로 가는지 확인합니다.

클로드 코드 입력창에 /usage를 입력합니다. /cost와 /stats는 /usage의 별칭이고, /stats는 같은 화면의 Stats 탭으로 열립니다. 맨 위 Session 칸의 예상 금액은 API 사용자를 위한 것이라 Pro·Max 구독자의 청구와는 관계없습니다. 구독 요금제라면 같은 화면에 사용량 막대와 함께, 최근 사용량을 스킬·서브에이전트·플러그인·MCP 서버별로 나눈 비율이 나오고, 그 사용량의 10% 이상을 차지하는 습관이 있으면 줄이는 방법 추천도 나옵니다.

추천 줄 앞의 비율은 그 추천이 해당하는 사용량의 몫이고, 그만큼 줄어든다는 뜻은 아닙니다. d나 w로 최근 24시간과 7일을 바꿔 보고, 'f to fix' 안내가 보이면 f를 눌러 처리할 수 있는 추천을 맡깁니다(v2.1.305 이상). /context는 컨텍스트 창이 무엇으로 차 있는지 격자로 보여 줍니다. 사용량을 늘 보고 싶다면 /statusline 뒤에 원하는 표시 내용을 적어 상태 표시줄을 만듭니다.

클로드 코드 입력창
/usage

확인Session 칸이 보이고, Pro·Max·Team·Enterprise 요금제라면 사용량 막대와 사용처 비율이 보입니다. 최근 사용량의 10% 이상을 차지하는 습관이 있으면 추천 줄도 나옵니다

STEP 2일이 바뀌면 /clear, 이어 갈 때는 /compact3분

이 단계에서는 쌓인 대화를 비우거나 요약해서 요청마다 다시 보내는 양을 줄입니다.

관련 없는 일로 넘어갈 때는 /clear로 빈 대화를 시작합니다. 나중에 돌아올 대화라면 /clear 뒤에 이름을 적거나 미리 /rename으로 이름을 붙여 두고, /resume으로 다시 엽니다. 같은 일을 계속하는데 대화가 길어졌다면 /compact로 지금까지를 요약하고, 뒤에 무엇을 남길지 적어 줍니다.

공식 문서는 /clear에는 비용이 들지 않지만 /compact는 요약할 대화를 한 번 더 보내는 요청이라고 설명합니다. 캐시가 살아 있을 때는 대부분 캐시에서 읽어 부담이 작고, 오래 쉬어 캐시가 식은 뒤에는 대화 전체를 캐시 없이 처리해 가장 비쌉니다. 그래서 작업과 작업 사이에 직접 /compact를 실행하라고 권합니다. 잘못된 방향으로 간 대화는 압축하지 말고 /rewind로 앞 시점으로 돌아갑니다. 압축할 때마다 남길 내용은 CLAUDE.md의 '# Compact instructions' 제목 아래에 적어 둘 수 있습니다.

클로드 코드 입력창
/clear login-bug

확인빈 대화로 새로 시작하고, 이전 대화는 /resume 목록에 login-bug라는 이름으로 남습니다

클로드 코드 입력창
/compact 테스트 결과와 바꾼 파일 목록 위주로 남겨 줘

확인지금까지의 대화가 요약으로 바뀌고 같은 작업을 이어 갑니다

이렇게 말고한 세션에서 버그 수정, 문서 작성, 새 기능 개발을 하루 종일 이어서 시킵니다
이렇게일이 바뀔 때마다 /clear로 새로 시작하고, 다시 볼 대화에만 이름을 붙여 둡니다

STEP 3일에 맞는 모델 고르기2분

이 단계에서는 평소 작업은 Sonnet으로, 어려운 설계 판단만 Opus로 나눠 씁니다.

공식 문서는 대부분의 코딩 작업을 Sonnet이 잘 처리하고 Opus보다 비용이 적다며, Opus는 복잡한 설계 판단이나 여러 단계 추론에 남겨 두라고 권합니다. /model을 입력하면 고르는 창이 뜹니다. Enter로 고르면 새 세션의 기본값으로 저장되고, s를 누르면 이번 세션에만 적용됩니다. /model sonnet처럼 이름을 바로 적으면 Enter와 같이 기본값으로 저장됩니다.

모델은 세션을 시작할 때 정해 두는 편이 좋습니다. 모델마다 캐시가 따로 있어 작업 도중에 바꾸면 다음 요청이 대화 전체를 캐시 없이 다시 읽습니다. 간단한 일을 맡는 서브에이전트에는 설정에 model: haiku를 적습니다.

클로드 코드 입력창
/model sonnet

확인모델이 Sonnet으로 바뀌고 새 세션의 기본값으로 저장됩니다

별칭공식 문서 설명Anthropic API 기준 연결 모델
sonnet일상 코딩 작업용 최신 SonnetSonnet 5.5
opus복잡한 추론 작업용 최신 OpusOpus 5.5
haiku간단한 작업용 빠른 HaikuHaiku 5.5

STEP 4생각하는 양(effort) 맞추기2분

이 단계에서는 단순한 작업에서 추론 수준을 낮춰 출력 토큰을 아낍니다.

클로드 코드는 확장 사고(extended thinking)를 기본으로 켜 두고, 생각에 쓴 토큰은 출력 토큰으로 계산됩니다. /effort 뒤에 low, medium, high, xhigh, max 가운데 하나를 적으면 추론 수준이 바뀝니다. 낮을수록 단순한 작업에서 빠르고 저렴하며, Opus 5.5·Sonnet 5.5·Haiku 5.5는 따로 정하지 않으면 medium에서 시작합니다.

/effort만 입력하면 슬라이더가 나옵니다. Enter는 기본값으로 저장, s는 이번 세션에만 적용이고, max는 CLAUDE_CODE_EFFORT_LEVEL 환경 변수로 정한 경우가 아니면 이번 세션에만 적용됩니다. /effort auto는 저장한 수준을 지웁니다. 위 세 모델은 확장 사고를 끌 수 없어 effort로 조절하며, 구독이나 API 키로 쓸 때는 effort를 바꿔도 캐시가 유지됩니다.

클로드 코드 입력창
/effort low

확인지금 모델의 추론 수준이 low로 바뀌고 기본값으로 저장됩니다

STEP 5CLAUDE.md를 200줄 아래로 줄이기5분

이 단계에서는 세션마다 빠짐없이 읽히는 지시 파일을 가볍게 만듭니다.

CLAUDE.md는 세션마다 컨텍스트에 들어가므로, 특정 작업에만 필요한 긴 설명도 늘 토큰을 씁니다. 공식 문서는 파일당 200줄 아래를 목표로 빌드 명령, 코드 규칙, 폴더 구조처럼 매번 필요한 내용만 남기라고 안내합니다. 여러 단계로 된 절차는 필요할 때만 불러오는 스킬로, 코드 일부에만 해당하는 규칙은 .claude/rules/ 폴더의 경로 지정 규칙으로 옮깁니다.

경로 지정 규칙은 맨 위에 paths를 적어 두면 Claude가 그 경로의 파일을 다룰 때만 읽힙니다. @경로로 다른 파일을 가져오는 방식은 정리에는 좋지만 가져온 파일도 함께 읽혀서 토큰은 줄지 않습니다. 사람만 볼 메모는 <!-- --> 주석 블록으로 적으면 Claude에게 보내기 전에 빠집니다.

/memory로 파일을 열어 고치고, /context의 Memory files 목록에서 읽힌 파일을 확인합니다. 세션 도중에 프로젝트 루트나 사용자 CLAUDE.md를 고친 내용은 /clear나 /compact 또는 다시 시작한 뒤부터 적용됩니다. 아직 읽히지 않은 하위 폴더 CLAUDE.md와 paths 규칙은 읽히는 시점의 내용이 들어갑니다.

.claude/rules/api.md (예시)
---
paths:
  - "src/api/**/*.ts"
---

# API 규칙
- 모든 API 엔드포인트에 입력값 검증을 넣는다

확인Claude가 src/api 아래의 .ts 파일을 다룰 때만 이 규칙을 읽습니다

STEP 6구체적으로 부탁하고, 큰 일은 계획부터2분

이 단계에서는 Claude가 파일을 넓게 뒤지거나 같은 일을 다시 하는 경우를 줄입니다.

'이 코드베이스를 개선해 줘' 같은 막연한 요청은 넓은 범위를 훑게 만듭니다. 'auth.ts의 로그인 함수에 입력값 검증을 추가해 줘'처럼 파일과 할 일을 정해 주면 적은 파일만 읽고 끝낼 수 있습니다. 큰 작업은 Shift+Tab을 몇 번 눌러 모드 표시가 plan(계획 모드)이 되게 하거나 /plan으로 시작해서, Claude가 먼저 방법을 제안하고 내가 승인한 뒤에 고치게 합니다.

Claude가 엉뚱한 방향으로 가면 Esc로 멈추고 /rewind나 Esc 두 번으로 앞 시점으로 되돌립니다. 테스트 케이스나 기대하는 결과를 함께 주면 다시 고쳐 달라고 할 일이 줄어듭니다. 작업 중에 잠깐 궁금한 것은 /btw로 물으면 대화 기록에 남지 않습니다.

클로드 코드 입력창
/plan 로그인 실패 시 오류 메시지 정리

확인계획 모드로 들어가 그 작업의 계획부터 세웁니다

이렇게 말고이 프로젝트 좀 깔끔하게 정리해 줘
이렇게src/auth.ts의 login 함수에 이메일 형식 검증을 추가하고, tests/auth.test.ts에 실패 사례 테스트 2개를 넣어 줘. 다른 파일은 고치지 마

STEP 7읽지 않아도 될 것 줄이기3분

이 단계에서는 쓰지 않는 MCP 서버, 큰 폴더, 긴 명령 출력이 컨텍스트에 들어오지 않게 합니다.

MCP 도구 설명은 기본으로 쓸 때만 불러오지만 도구 이름과 서버 안내는 컨텍스트에 들어갑니다. /mcp로 서버 목록을 열어 지금 쓰지 않는 서버를 끕니다. 공식 문서는 gh, aws 같은 CLI 도구가 MCP 서버보다 컨텍스트를 덜 쓴다고 설명합니다. 테스트 실행이나 로그 분석처럼 출력이 긴 일은 서브에이전트에 맡기면 긴 출력은 그쪽에 남고 요약만 돌아옵니다. 다만 서브에이전트가 보내는 요청도 사용량에 들어가므로, 간단한 일을 맡길 때는 작은 모델을 지정합니다.

읽을 필요가 없는 폴더는 설정 파일의 Read 거부 규칙으로 막을 수 있습니다. 공식 문서는 이 규칙을 .env 같은 민감한 파일을 막는 용도로 소개하고 토큰 절약 효과는 따로 말하지 않으므로, 빌드 결과물이나 로그 폴더에 쓰는 것은 편집부가 응용한 방법입니다. .claudeignore 파일은 효과가 없으니 그 항목도 이 규칙으로 옮깁니다.

클로드 코드 입력창
/mcp

확인연결된 MCP 서버 목록이 열리고 서버를 끄거나 켤 수 있습니다

.claude/settings.json (예시)
{
  "permissions": {
    "deny": [
      "Read(./dist/**)",
      "Read(./logs/**)"
    ]
  }
}

확인Claude의 파일 읽기 도구가 dist, logs 폴더를 읽지 못하게 막습니다. Grep·Glob에는 최선의 노력으로만 적용됩니다. 설정이 읽혔는지는 /status의 Setting sources 줄에서 확인합니다

보너스 · 긴 세션에서 사용량이 늘어나는 경우 점검
  1. 구독 요금제 안에서는 메인 대화의 캐시가 1시간, API 키·사용 크레딧·클라우드 제공업체에서는 5분 유지됩니다. 그보다 오래 쉬고 보낸 첫 메시지는 대화 전체를 다시 처리합니다
  2. 오래 비울 대화는 떠나기 전에 /compact로 줄여 둡니다. 캐시가 식은 뒤의 /compact는 대화 전체를 캐시 없이 읽어 더 비쌉니다
  3. /loop 같은 세션 예약 작업은 쉬는 동안에도 간격마다 대화 전체를 보내므로, 필요 없어지면 멈춥니다
  4. 에이전트 팀(agent teams)은 팀원마다 컨텍스트를 따로 써서, 팀원이 계획 모드로 일하면 보통 세션보다 토큰을 약 7배 씁니다
솔직히 한계
  • 명령과 설정은 2026년 10월 27일 공식 문서에서 확인했고 직접 실행해 보지는 않았습니다. 화면이나 이름이 다르면 claude --version으로 버전을 확인하고 공식 문서를 다시 봅니다.
  • /usage의 금액과 사용처 비율은 지금 컴퓨터의 기록으로 계산한 추정치입니다. 정확한 청구와 한도는 claude.ai 요금제 설정이나 Claude Console 사용량 페이지에서 확인합니다.
  • 압축하면 경로 지정 규칙과 하위 폴더의 CLAUDE.md도 요약에 묻혔다가 필요할 때 다시 읽히니, 꼭 지킬 규칙은 프로젝트 루트의 CLAUDE.md에 둡니다. effort를 낮추면 복잡한 작업의 결과가 나빠질 수 있습니다.
  • Read 거부 규칙은 grep -r처럼 파일 이름을 적지 않는 명령이나 스크립트가 직접 여는 파일까지 막지는 못합니다. 운영체제 수준에서 막으려면 샌드박스를 켭니다.
