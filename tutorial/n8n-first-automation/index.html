RSS Read부터 Send Email까지의 화면은 같은 설정으로 만든 워크플로 파일을 가져와 찍었습니다. API 키와 메일 비밀번호는 넣지 않았기 때문에 시험 실행은 AI 요약 앞 단계까지만 진행했습니다. n8n 화면이 영어라서 버튼 이름도 영어 그대로 적었습니다.

STEP 1n8n을 열 곳 정하고 실행하기10분

이 단계에서는 n8n 클라우드와 내 PC 설치 가운데 하나를 골라 편집기를 엽니다.

설치 없이 바로 써 보려면 n8n 클라우드 무료 체험이 가장 빠릅니다. 공식 문서에 따르면 체험 기간은 14일이고 프로(Pro) 요금제 기능을 실행 1,000회 한도 안에서 쓸 수 있으며, 기간이 끝날 때까지 유료로 바꾸지 않으면 인스턴스가 삭제됩니다. 내 PC에서 무료로 쓰려면 Node.js를 설치한 뒤 터미널에서 npx n8n을 실행하고 브라우저로 http://localhost:5678 에 들어갑니다. 처음 열면 'Set up owner account' 화면이 나오는데, 내 PC에 설치한 n8n에 로그인할 때 쓰는 관리자 계정을 만드는 곳입니다.

공식 npm 설치 문서는 Node.js 20.19~24.x를 적어 두었지만, 2026년 10월 27일 기준 최신 2.45.4 패키지는 Node.js 24 이상을 요구하므로 24를 설치합니다. 문서는 npm 설치가 n8n 3.0부터 되지 않는다고 예고하며, 새 설치에는 Docker 기반 한 줄 설치(curl -fsSL https://get.n8n.io | sh)를 권합니다. 이 방법을 쓰려면 Docker와 docker compose v2가 먼저 깔려 있어야 합니다. 윈도우의 명령 프롬프트와 파워셸에서는 이 명령이 돌지 않으므로, 문서는 Docker Desktop의 WSL2 연동을 켠 WSL에서 실행하기를 권합니다.

STEP 2새 워크플로에 매일 8시 트리거 달기5분

이 단계에서는 빈 워크플로를 만들고, 매일 아침 8시에 시작하도록 Schedule Trigger를 설정합니다.

워크플로가 하나도 없을 때는 첫 화면의 'Build a workflow'를, 이미 있을 때는 오른쪽 위 'Create workflow'를 누릅니다. 캔버스 가운데 'Add first step'을 누르면 무엇으로 시작할지 고르는 목록이 열리고, 여기서 'On a schedule'을 고릅니다. 설정 창에서 Trigger Interval은 Days, Days Between Triggers는 1, Trigger at Hour는 8am, Trigger at Minute는 0으로 둡니다. 왼쪽 위 'My workflow'를 눌러 이름을 '매일 아침 AI 소식 요약'처럼 바꿔 두면 나중에 찾기 쉽습니다.

시간대도 함께 확인합니다. 셀프 호스팅 n8n의 기본 시간대(GENERIC_TIMEZONE)는 America/New_York이라서 그대로 두면 한국 시각 오전 8시에 돌지 않습니다. 워크플로 이름 옆 점 세 개 메뉴의 Settings에서 Timezone을 Asia/Seoul로 바꾸면 이 워크플로가 한국 시각을 따릅니다. 클라우드는 클라우드 콘솔의 Instance settings에서 인스턴스 전체 시간대를 바꿀 수 있습니다.

STEP 3RSS Read로 최신 글 목록 가져오기5분

이 단계에서는 RSS 주소를 넣어 사이트의 최신 글 목록을 가져옵니다.

Schedule Trigger 오른쪽의 +를 누르고 검색 칸에 RSS를 입력해 'RSS Read'를 고릅니다. 꼭 채워야 하는 설정은 URL 한 칸이고, 여기에 구독하려는 뉴스나 블로그의 RSS 주소를 붙여 넣습니다. 'Execute step'을 누르면 오른쪽 OUTPUT에 글이 한 줄씩 나옵니다. 아래 화면은 시험용으로 파이썬 패키지 저장소 PyPI가 공개하는 anthropic 라이브러리 릴리스 RSS를 넣은 결과이고, 글 40개가 들어왔습니다.
용어 · RSS사이트가 새 글 목록을 프로그램이 읽기 쉬운 형식으로 공개하는 주소입니다.
용어 · 아이템(item)n8n에서 노드 사이를 오가는 데이터 한 건입니다. 글이 40개면 아이템도 40개이고, 아이템마다 title(제목), link(주소), contentSnippet(본문 일부) 같은 칸이 생깁니다.

STEP 4Limit와 Aggregate로 다섯 개를 한 묶음으로5분

이 단계에서는 피드 맨 앞의 글 다섯 개만 남기고, AI에게 한 번에 넘길 수 있도록 하나로 묶습니다. 대부분의 피드는 최신 글을 맨 앞에 둡니다.

n8n 문서에 따르면 노드는 들어온 아이템을 하나씩 따로 처리합니다. 40개를 그대로 넘기면 요약과 메일도 40번 실행되므로, 먼저 Limit 노드를 붙여 Max Items를 5, Keep을 First Items로 둡니다. 이어서 Aggregate 노드를 붙여 Aggregate는 'All Item Data (Into a Single List)', Put Output in Field는 articles, Include는 Specified Fields로 고르고 Fields To Include에 title, link, contentSnippet을 적습니다. 실행하면 글 다섯 개가 articles라는 목록 하나에 담겨 1 item이 됩니다.
이렇게 말고RSS Read 바로 뒤에 AI 노드 붙이기(요약 메일 40통)
이렇게Limit와 Aggregate로 하나로 묶은 뒤 AI 노드에 넘기기(요약 메일 1통)

STEP 5Basic LLM Chain에 요약 지시문 넣고 모델 연결하기7분

이 단계에서는 AI 노드에 요약 지시문을 넣고, 실제로 글을 쓸 AI 모델을 연결합니다.

Aggregate 뒤에 'Basic LLM Chain'을 붙이고 Source for Prompt (User Message)를 'Define below'로 바꾼 뒤, Prompt (User Message) 칸에 아래 지시문을 붙여 넣습니다. 마지막 줄의 {{ JSON.stringify($json.articles) }}는 앞 노드가 만든 articles 목록을 글자로 바꿔 넣으라는 표현식이고, 편집 창 오른쪽 Result에서 실제로 들어갈 내용을 미리 볼 수 있습니다. 노드 아래 Model 자리의 +를 눌러 Google Gemini Chat Model 같은 모델 노드를 고르고, Credential에서 내 API 키를 연결합니다. 클라우드에서는 같은 자리에서 'Use Gateway credits'를 고르면 키 없이 쓸 수 있습니다.

Gemini를 쓴다면 Google AI Studio에서 만든 API 키를 Credential 창의 API Key 칸에 넣습니다. 키가 없으면 Model 칸에 'Set up credential to see options'만 보이고, 실행하면 'Node does not have any credentials set' 오류가 납니다. Gateway credits는 클라우드 스타터·프로 요금제와 무료 체험에서만 쓸 수 있습니다. 무료 체험 중에는 충전할 수 없고, 잔액이 0이 되면 이 크레딧을 쓰는 노드가 실패합니다.

용어 · 표현식{{ }} 안에 쓰는 식으로, 실행할 때 앞 노드의 실제 값으로 바뀝니다. 왼쪽 INPUT의 필드를 칸으로 끌어다 놓아도 만들어집니다.
복사해서 쓰는 프롬프트
아래는 오늘 받은 소식 목록입니다. 항목마다 제목(title), 링크(link), 본문 일부(contentSnippet)가 있습니다. 1) 맨 위에 오늘 소식 전체를 세 줄로 정리해 주세요. 2) 그 아래에 소식마다 한국어로 한두 문장 요약을 쓰고 끝에 링크를 붙여 주세요. 3) 목록에 없는 내용은 추측해서 덧붙이지 마세요. 소식 목록: {{ JSON.stringify($json.articles) }}

STEP 6Send Email로 내 메일함에 보내기7분

이 단계에서는 AI가 쓴 요약을 메일 본문에 넣어 보내도록 설정합니다.

Basic LLM Chain 뒤에 'Send Email'을 붙이고 From Email과 To Email에 내 주소를, Subject에 오늘의 AI 소식 {{ $now.toFormat('yyyy-MM-dd') }}를 적습니다. Email Format은 기본값이 HTML이므로 Text로 바꾸고, 새로 생긴 Text 칸에 {{ $json.text }}를 넣습니다. Basic LLM Chain은 AI의 답을 text라는 칸에 담아 넘깁니다. 이 글의 시험 실행은 AI 단계 앞에서 멈췄으므로, 키를 연결한 뒤 처음 실행할 때 Basic LLM Chain의 OUTPUT에 text 칸이 있는지 한 번 확인합니다. Options에서 Append n8n Attribution을 끄면 메일 끝에 'This email was sent automatically with n8n' 문구가 붙지 않습니다.

Credential의 'Connect to SMTP'를 누르면 메일 서버 정보를 넣는 창이 열립니다. Gmail은 2단계 인증을 켠 뒤 Google 계정에서 앱 비밀번호를 만들어야 이 방식으로 보낼 수 있고, 아래 표의 값을 넣습니다. 회사 메일은 SMTP 정보를 메일 관리자에게 확인합니다. 클라우드를 쓴다면 Send Email 대신 Gmail 노드를 붙이고 'Sign in with Google'로 연결하는 방법도 있습니다. 메신저로 받으려면 Slack, Microsoft Teams, Telegram 노드를 쓰면 됩니다.

STEP 7시험 실행하고 Publish로 켜기6분

이 단계에서는 전체 흐름을 한 번 돌려 보고, 매일 아침 저절로 돌도록 게시합니다.

캔버스 아래 'Execute' 버튼(문서 이름은 Execute workflow)을 누르면 예약 시각을 기다리지 않고 바로 한 번 실행됩니다. 성공한 노드에는 초록 체크가, 노드 사이 선에는 '5 items', '1 item' 같은 개수가 표시되고, 문제가 생긴 노드는 빨간 테두리로 바뀝니다. 메일이 제대로 오면 오른쪽 위 'Publish'를 눌러 게시합니다. 문서에 따르면 Schedule Trigger로 시작하는 워크플로는 게시해야 정해진 시각에 돌고, 게시한 뒤에 고친 내용은 다시 Publish해야 반영됩니다.

자격 증명이 빠진 노드가 있으면 Publish 버튼이 눌리지 않고 '2 nodes have issues, fix them before publishing.' 같은 안내가 뜹니다. 아래 화면은 키를 넣지 않고 실행한 결과라서 RSS Read, Limit, Aggregate까지 성공하고 Basic LLM Chain에서 멈췄습니다. 지난 실행은 위쪽 Executions 탭에서 볼 수 있습니다.

보너스 · 켜 두기 전에 확인할 것
  1. 워크플로 Settings의 Timezone이 Asia/Seoul로 되어 있습니다
  2. 앱 비밀번호와 API 키는 Credential 창에만 넣었고, 노드 설정 칸이나 메모에는 적지 않았습니다
  3. 가격 페이지는 실행 1회를 워크플로 전체가 한 번 도는 것으로 셉니다. 매일 한 번이면 한 달에 30회 안팎입니다
  4. 완성한 워크플로는 점 세 개 메뉴의 Export JSON으로 내려받아 두고, 필요할 때 Import > From file로 다시 가져옵니다
솔직히 한계
  • 내 PC에 설치한 n8n은 PC와 n8n이 켜져 있을 때만 예약 작업을 합니다. Schedule Trigger의 Settings 탭에 'If Execution Is Missed' 옵션이 있지만, 기본값은 놓친 실행을 건너뛰는 'Don't Run Missed Executions'입니다. 이 값을 'Run the Most Recent Missed Execution'으로 바꾸면, 놓친 시각 가운데 가장 최근 한 번을 n8n이 다시 켜졌을 때 실행합니다. 문서에 따르면 이 옵션은 2.45.0부터 기본으로 켜진 durable scheduler에서만 작동합니다.
  • RSS Read는 실행할 때마다 피드에 있는 글을 처음부터 다시 읽고, 전에 받은 글을 거르지 않습니다. 피드에 새 글이 없으면 같은 글이 다시 요약되어 옵니다. 새 글이 올라올 때만 돌리고 싶다면 RSS Feed Trigger 노드를 쓰는 방법이 있습니다. 또 이 글의 워크플로는 RSS 주소 하나만 읽습니다.
  • 공식 문서는 npm·npx 설치가 n8n 3.0부터 되지 않는다고 예고했고, 실제로 2.45.4를 npm으로 실행하면 앞으로는 공식 Docker 이미지로만 실행할 수 있게 된다는 경고가 나옵니다. 오래 쓸 생각이라면 Docker 기반 한 줄 설치나 클라우드를 고려합니다.
  • AI 요약은 원문에 없는 내용을 지어낼 수 있으므로 중요한 소식은 링크를 열어 원문을 확인합니다. 모델 API 사용료는 각 제공사 요금표를 따릅니다. 클라우드 Gateway credits도 요청마다 잔액에서 차감되고, 잔액이 떨어지면 AI 노드가 멈춥니다.
  • 가격과 체험 조건은 2026년 10월 27일 가격 페이지와 공식 문서 기준이며 바뀔 수 있습니다. 라이선스는 회사 내부 업무와 개인·비상업 용도의 사용을 허용합니다. n8n 자체를 고객에게 열어 고객이 자기 계정을 연결하고 워크플로를 만들게 하는 서비스처럼 이 범위를 벗어나는 용도에는 n8n과 별도 상업 계약이 필요합니다.
